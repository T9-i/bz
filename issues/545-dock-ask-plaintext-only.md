# 545 · 询问框的正文只能是一段段纯文本，要摆表的工具只能写成散文

## 症状

运行中询问（`[bz-ask]`）弹出来的框，正文由 `body` 一个字段给，UI 按 `\n` 分成段落渲染。
第一个真用它的工具（steam-classify：写 Steam 分类前问一句）要摆的是**一张核对表** ——
哪几款游戏分别进哪个分类；纯文本排出来是：

```
扫出 4 款未归类：4 款可以直接写，0 款要你定（这次不写）。

要写进 Steam 收藏分类的（4 款）：
  刷宝 · Roguelike　咖啡星矿工、咖啡星矿工：序章
  工具 · 非游戏　龙之信条2：角色编辑
  模拟经营 · 小店　度假咖啡厅模拟器

做法：Steam 现在没在跑，直接写入（写完也不擅自启动它）。写入前自动备份。
```

行与行只是同一字号同一颜色的一串字，分组靠两个全角空格，人得逐行读才知道自己要点的是什么。
用户的原话：「里面的内容也由脚本写 html 可以自定义样式布局，可以做的精美好看些」。

## 根因：正文的载体只有一种，而这一屏要的是版式

`BzAskRequest.body: string` 是**唯一**的正文通道，且 `confirmAsk` 明确只当文本渲染
（`el('p', ..., p)`，`textContent`）—— 这是对的：工具输出不可信，`innerHTML` 进来等于给每个
工具发一张 XSS 通行证。问题不在渲染得不对，而在**没有第二条路**：想摆版式的工具无处可去，
只能把版式信息压成空格和冒号。

同一件事在详情页那边已经解过一次（ADR-0243 展示板）：**bz 不替每个工具设计版式，工具自己画，
装在沙箱 iframe 里**。询问框正文是它的同类场景，只是落点在弹窗里。

## 修法

协议加一个可选字段 `bodyHtml`（ADR-0244）：

| | 载体 | 渲染 |
|---|---|---|
| 纯文本 | `body` | 按 `\n` 分段、`textContent`（**不变**，现存工具零影响） |
| 版式 | `bodyHtml` | `sandbox="allow-same-origin"` 的 iframe + `srcdoc`，**不给 `allow-scripts`** |

- 两样都给时 HTML 胜；`body` 不退场，当兜底（进记录、HTML 超上限被退回时用）。
- 上限：字节 **128 KB**（超了退回纯文本并**说明**）、高 **360 px**（超了框内滚）；框宽
  纯文本 460 → HTML 560。
- 主题变量与「按内容量高」的逻辑与展示板**共用一份实现**（`frameBaseStyle` / `fitFrameHeight` /
  `sandboxFrame`，原 `board*` 三个私有函数改名共用）—— 两份会漂。
- 按钮与倒计时仍在框外、仍归 bz：`confirmText` / `cancelText` 只改字。

## 刻意没改

- **超时 = 取消**、**没人应答 = 取消**、焦点落在取消 —— 这一屏的语义一条没动，改的只是正文怎么画。
- **不给 `allow-scripts`**，哪怕写脚本的人本来就能在本机跑命令。
- 展示板的 512 KB / 520 px 两个上限**没跟着动**：那是「一眼看完的几行数」的口径，与弹窗正文是两件事。
