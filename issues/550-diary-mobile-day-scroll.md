# 550 · 日记本窄屏重做：一天一卷、正常滚动、滚到头换天

> 用户 2026-10-16 连续三轮拍板的合并落地。前一轮（书页铺满 + 翻页全废的真因 + 库空转守卫）
> 记在 `issues/549-diary-mobile-fill-and-flip.md`；本票是**形态重做**，不是修 bug。
> ADR 落点：`docs/adr/adr-0230-diary-book-ui.md` 决策 12。

## 用户原话（三轮）

1. 「日记本在移动端上关闭按钮距离顶部不是 44px，距离顶部的 44px 是空白，这不对应该也有日记本的背景，
   翻页有 bug，异常卡顿，写新日记保存后不显示等等各种问题」
2. 「异常卡顿的真凶解决吧，另外一次性渲所有日记是不是也是原因」
3. 「改一下翻页的动画，简单为主。然后如果滚动到日记的底部或顶部，再往下滚动自动下一条或上一条。
   底部栏只留图标，不用文字了」
4. 「移动端去掉翻页特效，一次展示一天的日记，上一页下一页和中间页数去掉，用户可以正常滚动页面，
   滚动到当天日记的顶或底，自动翻到下一天或上一天」

前两轮（1、2）已随 `issue 549` 落地。本票 = 3 + 4，其中第 4 条**推翻了第 3 条里我刚加的两样**
（「底部栏只留图标」保留；「上一页/下一页 + 中间页数」撤销）。

## 结论：窄屏不再走翻页库

需求里「一天一屏」和「页面正常滚动」这两条放在一起，只有一种自洽解：**窄屏不看 StPageFlip**。
库的页是定尺的，往它里面塞第二个滚动维度，必然和它的翻页手势、连它的 aspect 盒一起打架
（549 那条真因就是这么来的）。所以窄屏整条换掉：

| | 桌面（>720px） | 窄屏（≤720px） |
|---|---|---|
| 版式 | 跨页书（左/右两页并排） | 一天一卷，一次只摆一卷 |
| 页的单位 | 分页算法切出来的纸（一天可占多页） | **一天**（`groupByDay`，不切段、不拆页） |
| 翻页 | StPageFlip（flippingTime 240ms、`drawShadow: false`） | 无。纯显隐，零过渡 |
| 换页手势 | 拖拽 / 滚轮 / ← → | 滚轮 / 触摸竖滑，**只在滚到当天的顶或底之后** |
| 滚动 | 无（纸是定尺的） | `.bz-diary-page-inner` 正常滚 |
| 页码 / 翻页钮 | 页码有、翻页钮无 | 两样都没有 |

## 关键实现点

- **`groupByDay()`**：`this.pages` 在窄屏 = 天列表（按日戳块的 `data-date` 分组），于是
  **页号即天号**。书口索引 / 台历跳日 / 检索定位这三条按页号算的老路**一行没改**即可用
  —— 这是整票里省事最多的一处。
- **不做 `splitParagraph`**：那条路会逐行切开长段落，而且改的是**原元素**（`ui.ts::splitParagraph`
  末段两个 `Range.deleteContents()`）。窄屏一天就该是完整的一天。顺带省掉一轮逐块 reflow
  （210 页量级时这一步是全量成册里最大的一笔，而它读出来的高度窄屏没人用）。
- **边判**：滚轮与触摸各一条，先把滚动让给这一天，滚到头那一下才换天。往下落**下一天开头**、
  往上回**上一天末尾**，所以一路往下滚就是一篇接一篇。触摸那条**不要求内容溢出**——窄屏没有
  别的换天手势，短的一天也必须能滑走。
- **触屏长按豁免跟着搬**：`.bz-diary-day` 与 `.bz-diary-page-item` 同为「纸面」角色，一并
  `user-select: none`（issue 217 的教训：正文可选中的话系统选择浮标会掐死长按计时，便签菜单永不出）。
- **工具条两套面孔**：纯层同一份 markup 吐 `<b>墨字</b>` + `.bz-ic` 图标，桌面档藏图标、
  窄屏档藏字。窄屏那条 46px 高的玻璃栏上只留图标（用户拍板）。

## 顺带的两处收尾（同轮）

- 纸左右通栏 `100vw`：上一轮已把 `pageWidth()` 改成只读书宽，「CSS 与 JS 两份页宽」这个前提没了，
  所以这里可以放心重写成 `100vw`。
- `drawShadow: false`：库有这一项（`page-flip.browser.js` 里 `setShadowData` 首行就判它），
  之前的 `.d.ts` 没声明。关了之后翻页只剩位置/角度在动，配 240ms 就是一记干净的转向。
