# 543 · 信任确认框把核对表排成了散文，九行事实没有重点

## 症状

导入工具声明时弹出的信任框（`confirmTrust`）排版一团糟：全篇居中，工具名、命令、两条长路径、
节奏、参数、两段说明都是同一个字号同一个颜色；路径按词居中折行、折出参差的碎块；
「会跑什么」和「建立信任之后…」一样重。用户的原话是「信息没重点」。

节奏那一行最刺眼，实际渲染出来是：

```
节奏：每天一次09:00 前（早上 9 点；模拟器开着关着都行 —— 默认会自动拉起，跑完关回去）（自动化；bz 会在它开着时按节奏跑）
```

两个括号连着出现 —— 作者写在声明里的 `schedule.note` 与调用方拼的系统套话叠在一起，
像一句话被念了两遍。

## 根因：组件选错了，不是样式写错了

`confirmTrust` 走 `core/flow-dialog` 的 `openFlowDialog`，而那个组件的 `message` 是**一段散文**：

```ts
'<p>' + escapeHtml(message).replace(/\n/g, '<br>') + '</p>'
```

`\n` 只换成 `<br>`，不构成任何层级；外层 `#__shared_confirm_popup__` 又是
`align-items: center; text-align: center` + `width: min(400px, …)`。

这套形制是给「确定删除？」这类**一句话问句**设计的 —— 一句话摆得下，居中反而显得郑重。
而信任框要摆的是**一张核对表**（名 / 描述 / 命令 / 工作目录 / 声明文件 / 节奏 / 参数 + 三句前提）。
核对表被排成散文，就没人能核对了。这才是「没重点」的来源，居中只是它的表征。

## 修法

域内自绘 `uiModal`，不再用 core 流程框。两处先例：同域的规则编辑框
（`.bz-dock-rulemodal`）、跨域的 attach 搬移预览（也是从 `openFlowDialog` 升到 `uiModal` 自绘）。
**core 一行没动** —— 流程框被 20 多个域共用，为一个框改它的契约不划算。

层级按**决策要用到的顺序**排，不按字段顺序：

| | 内容 | 形制 |
|---|---|---|
| ① | 它是什么 | 工具名 `--bz-font-title`（17px，比弹窗标题高一档）+ 描述 |
| ② | **会跑什么** | 等宽代码块 + 底 + 边框 —— 信任的对象就是这条命令，它是这屏的重点，不是备注 |
| ③ | 配套事实 | 标签定宽一列（`5.5em`）、值左对齐起；路径等宽且 `overflow-wrap: anywhere` |
| ④ | 信任语义 | `--bz-text-3` 小字 + 一条发丝线隔开，不与事实抢注意力 |

其余：全篇左对齐；宽度 400 → 520（这屏要摆两条完整路径）；移动端（≤768px）标签改到值上方独占一行。

顺手修掉节奏的重复括号：`scheduleTextOf(s, withNote = true)` —— 默认行为不变（详情页照旧带作者
提示），信任框传 `false`。**没有另写一个格式化函数**，声明那份与用户覆盖那份仍是同一份口径。

顺带删掉因这次改动变成死代码的 `scheduleText()`（唯一调用方就是被换掉的这段）。

## 刻意没改

- **焦点仍在主动作（回车 = 接受）**，与旧流程框一致。只改排版；顺手把「回车确认」变成
  「回车取消」是另一个决定，不该夹带进一次排版修复。
- `uiModal` 不像 `openFlowDialog` 自带「新框顶替旧框」语义，显式补了一道防重入：
  `.bz-dock-trustmodal` 已在 DOM 里就直接返回未确认（安全的那一侧）。
- `schedule.note` 在信任框里不再显示 —— 它归详情页。**没有删数据，只是不在这一屏出现。**

## 验证

- `tsc --noEmit` 干净；
- `node scripts/test-affected.mjs`：67 文件 / 1006 项全过；
- 预览壳 `http://localhost:5177/prototypes/dock/prototype.html` → 点行头的「+」（导入工具声明），
  壳里的假选择器会递一份待登记声明，正是这一框。

## 踩到的坑（留给下一个在 worktree 里出预览产物的人）

在 worktree 里 `build-preview.mjs`，esbuild 会把 `node_modules/.pnpm/...` 解析成
`../../bz/node_modules/.pnpm/...`（junction 的真实路径），产物头部的 `源指纹` 注释也随之变化。
**这份产物不能提交** —— 提交到 master 后 `tests/preview-freshness.test.ts` 会立刻比出不一致。
正确顺序：源码在 worktree 改并过门禁，产物回主仓出。
