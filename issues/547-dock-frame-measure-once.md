# 547 · 展示板还是那根滚动条：量高只量了一次，隐藏条又挂错了元素

## 症状

546 改完（去掉高度上限、滚动交回宿主）用户回：「还是有滚动条」，截图与上一轮几乎一样 ——
展示板右侧一根带上下箭头的原生条，拇指几乎顶满轨道。

## 根因：两条，都用无头 Edge 实测钉住了

### ① 高度只在 `load` 时量一次 —— 量到 0（或量短了）就永远不纠正

`fitFrameHeight` 原来是：`load` → 量 `scrollHeight` → `if (h > 0)` 写高度。两次实测：

- **面板关着的时候也会渲染**（刷新 / 运行结束后的重渲染），而 `display:none` 的框里文档**没有布局**：

  ```
  框 display:none 时量高：scrollHeight=0；显示后=984
  ```

  量到 0 → 那个 `if (h > 0)` 直接跳过 → **这一帧之后再也没人量过** → 框停在默认 150px、
  内容溢出、框里长出一根条（而且它跟父面板的显示状态无关了，永远那个样）。
- **emoji / 字体在 `load` 之后才落地**，内容会长高一点点：`984 → 1944`（同一次实测）。
  量到的旧高度就短了那么一点，溢出的那一点点正好够长出一根条 —— 与截图里「拇指几乎顶满轨道」
  （= 溢出很小）完全吻合。

### ② 隐藏条挂错了元素：挂 `<body>` 无效，得挂**根元素** `<html>`

546 往框内基线的 `<body style="…">` 里塞了 `scrollbar-width: none`。实测：

| 挂哪 | 框内条占位 |
|---|---|
| 什么都不挂 | **15px**（可见） |
| 挂 `<body>` | **15px**（**无效** —— 今天实现的做法） |
| 挂 `<html>` | **0px** ✓ |
| 父侧 JS 写 `documentElement.style` | **0px** ✓ |

原因：**框里的滚动条是视口滚动条，归根元素管，而 `scrollbar-width` 不继承** —— 挂 body 上
对它一点作用都没有。顺带印证了 core 那条界面级规则（ADR-0122）的边界：它是 CSS，**跨不过文档
边界**，框里永远够不着（同一张实测表里，`bz-` 前缀的宿主容器条占位是 0，规则的宿主半边是好的）。

## 修法

- `fitFrameHeight`：立刻量一次 + `ResizeObserver` 盯着框内 `body` / `documentElement` 的尺寸。
  隐藏时它不派发，一旦显示、布局从 0 变成真高度就会派发 —— 这正是「关着渲染」那条路需要的；
  内容后续长高也照样跟上。**差 1px 不动它**：否则「量高 → 框变高 → 框内重排 → 再量」会互相
  追着改。
- 隐藏条那条挪到 `frameRootStyle()`，挂在 srcdoc 的 `<html style="…">` 上（`frameBaseStyle()`
  保持只管 body 基线，并且注释里写明「别把这条并进去」——不继承，加了也没用）。
- 两条守卫进 `tests/dock/frame-base-style.test.ts`：根元素带隐藏条、body 基线不许带；
  量到 0 之后靠 RO 补上、差 1px 不动、内容变高跟上、没有 RO 的老环境退化成「只量一次」不抛。

## 刻意没做

- **不给框里注入 `<style>`**：那会在铁律 4（唯一注入点）上开第二个口子。`style` 属性够用 ——
  隐藏视口条只需要根元素这一条。
- **不追求「连框内嵌套滚动区也隐藏」**：工具自己写的 `overflow: auto` 容器（比如它自己画一个
  长列表）要隐藏条，得它自己声明；bz 只能管到文档根，管到每一层就得注入样式表。
- **不把「量到 0」当成"内容为空"**：两者含义完全不同，所以是「先不设高、等能测到再设」，
  而不是「设成 0」。
