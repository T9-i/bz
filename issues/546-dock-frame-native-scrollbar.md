# 546 · 展示板与询问框里各长了一根原生滚动条

## 症状

用户发来展示板的截图（6 款未归类 + 一列明细），右侧一条带上下箭头的滚动条，配一句：

> 确认弹窗和展示窗口都不显示滚动条。

「不显示」= 这两个框里**都别**长滚动条。它们各自长了一根，而且是**原生**的：与宿主的细滚动条
完全不是一回事。

## 根因：滚动被放在了框里面

两个框都是「沙箱 iframe + 按内容量高」，但量高时**封了顶**：展示板 520 px（ADR-0243 定的），
询问框正文 360 px（ADR-0244 定的）。`fitFrameHeight` 取 `Math.min(内容高, 上限)` ——
内容一过顶，iframe 停在顶格，多出来的部分就只能**在框里滚**。

框里滚出来的滚动条有三个问题：

- **样式管不着**：它是浏览器给 iframe 文档画的，面板的 CSS 进不去（框里只有 bz 灌的那一小撮
  主题变量，连 `<style>` 注入都是另一个口子）；
- **不跟主题**：宿主滚动条是细的、跟皮肤走，它带箭头、跟着系统；
- **不该出现**：展示板那点内容本来就放得下 —— 520 px 是「别把运行台挤到屏幕外」的保守值，
  而这一屏只差一点点，于是为了那一点点挤出一根原生滚动条。

顺带暴露的第三件事：`browser 默认` 与 `iframe` 的滚动条不是「一个东西的两种皮肤」，
而是**两个不同的层**——框里的一切都归宿主管不着。

## 修法：框跟着内容长，滚动交回宿主

| | 谁滚 | 滚动条 |
|---|---|---|
| 展示板 | 面板内容区 `.bz-dock-body`（本来就是唯一滚动容器） | 宿主的 |
| 询问框正文 | 新增 `.bz-dock-ask-pane` | 宿主的 |

- `fitFrameHeight(frame)` 去掉 `maxHeight` 参数、不再 `Math.min` —— 框多少内容就多高。
- 询问框照抄 `memo` 编辑弹窗那一套（`.bz-memo-editor-popup` 的注释写着同一个结论：
  **「弹窗整体不再滚 —— 滚动移交内容区，保存钮行才能钉底」**）：弹窗 `overflow: hidden` →
  `.bz-dialog-body` / `.bz-dock-ask` 继续 `flex: 1 1 auto; min-height: 0` →
  正文区 `.bz-dock-ask-pane { flex: 1 1 auto; min-height: 0; overflow-y: auto }` →
  动作行留在滚动区外（`flex: none`），按钮与倒计时永远在手上。
- 描边 / 圆角 / 底色从**框**挪到**正文区**（`.bz-dock-ask-pane.is-framed`）：框会跟内容一样高，
  它自己的边框迟早滚出视线。
- 字节上限（512 KB / 128 KB）**不动** —— 那管体积（灌 srcdoc 的开销、别把手册塞进展示板），
  与滚不滚没关系。

## 刻意没做

- **不隐藏滚动条**（`scrollbar-width:none` 之类）：域内自绘滚动条是铁律禁的，而且藏起来 = 内容
  看不见、还不知道下面有东西。要么放得下，要么滚 —— 后者交给宿主。
- **不给展示板恢复任何高度上限**：代价是它理论上能长到任意高（512 KB 管体积），所以它仍是
  「一眼看完的几行数」，别当日志写 —— 这条写在指南里，由写工具的人守。
- **不动字节上限**：两个上限是两件事，不该因为这次一起改。
