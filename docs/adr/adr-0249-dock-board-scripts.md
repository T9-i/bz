# ADR-0249 · 展示板允许跑脚本（推翻 ADR-0243 的「刻意不给」）

日期：2026-10-22 · 状态：已采纳 · 关联：ADR-0243（展示板，本文推翻其一条边界）、
ADR-0244（询问框，**不跟着改**）、ADR-0247（展示板动作，通道理由随之修订）、
`docs/dock-tool-guide.md` §5.2

## 背景

2026-10-22 用户提出：

> 白菜价雷达脚本展示窗增加一个搜索功能。

先试了两条不开脚本的路，都不成立：

1. **把搜索做成参数表单里的项**（填词 → 跑一次 → 脚本重画面板）。当场被否：
   「搜索为什么增加到运行台？？应该加到展示中啊」—— 搜索是「看」不是「跑」。
2. **严格纯 CSS**。面板现有的页签 / 排序 / 隐藏已拥有全是 `:checked` + `display:none`，
   但那是**预设状态**。CSS 没有「输入框的值包含某词」这种选择器，打字即时筛做不到 ——
   不是不肯写，是 CSS 的边界。

于是只剩一条路：让框里跑脚本。用户拍板：

> 允许脚本运行js，改吧

## 决策

### 1. 展示板框加 `allow-scripts`；询问框不加

`sandboxFrame()` 多一个 `allowScripts` 选项，**只有 `boardSection` 传 true**：

```
allow-same-origin allow-popups allow-popups-to-escape-sandbox allow-scripts
```

询问框（`bz-dock-ask-frame`，ADR-0244）维持原样：那一屏只问一句话，递进来的 HTML 没有理由
需要执行能力。差别写进代码注释与测试，别让后来的人「顺手对齐」。

`allow-top-navigation` 仍然不给：框能跑代码，但顶不掉整个面板。

### 2. 承认这次的代价：同源 + 脚本 = 沙箱的隔离不再是安全边界

ADR-0243 §2 与 ADR-0247 的备选表都明确写过「`allow-same-origin` + `allow-scripts` 会让沙箱
形同虚设（MDN 警告）」。这次是**知情地接受**它，理由三条：

- **工具本来就是被信任的**：它能在这台机器上跑任意命令、读写 vault。框里能碰面板 DOM，
  不比它已有的能力多出什么 —— 沙箱在这里挡的从来不是「恶意工具」，而是「手滑」与「日后被
  当成能力用」。
- **要画的东西确实需要它**：搜索框、批量勾选、任何「读输入 → 改列表」的交互，预设状态表达不了。
- **替代方案更脏**：宿主代筛（bz 在框外拿 `contentDocument` 改类名）要维护一套跨文档协议，
  且每个新交互都要 bz 加代码 —— 最后长成「面板的一半逻辑住在插件里」，比放开脚本更不可控。

**代价写在这里，别假装没有**：从这一刻起，`panel.html` 里的代码和工具本身同级可信任。
新装一个来路不明的工具，等于把它的 HTML 放进插件自己的 DOM 旁边。

### 3. ADR-0247 的通道不变，但理由要改

`#bz-act:` 仍然由宿主的 click 监听接管，仍然过「声明即白名单 + 参数掐口」两道门。
原来写的理由是「框里跑不了脚本，所以只能走宿主」——**这条理由没了**，但结论反而更强：

> 动作的两道门必须由宿主做，交给框里自己判断就等于没有门。

也就是说：框里现在能写 JS，更要把「点了这一下能不能跑」的决定权留在外面。

## 后果

**好的**

- 工具终于能画真正的交互（第一个消费者：白菜价雷达的搜索框，打字即时筛 `data-bz-item`）；
- bz 侧改动很小：一个选项 + 一处传参，没有新增跨文档协议；
- 询问框的边界保持原样，展示板与询问框从此按用途分开。

**要认的**

- **沙箱不再是安全边界**：它现在只保证「样式与 DOM 只影响框内 + 顶不掉面板」。
  同源 + 脚本的组合让框能读到 `parent` 的 DOM —— 这是这次决策的核心代价。
- **面板更重了**：脚本可以写死循环、可以改 DOM 到量高算不准（`fitFrameHeight` 靠
  `ResizeObserver`）。工具作者要自己负责别把自己的框搞坏。
- **文档口径要一起改**：`dock-tool-guide.md` 从「别指望 `<script>` 会跑」变成「可以跑，
  但别指望外部资源」（相对路径与 `file://` 仍然拿不到）。
