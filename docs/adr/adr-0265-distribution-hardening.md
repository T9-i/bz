# ADR-0265 对外分发的六处硬化：多库分家、离线出路、文件真在

- 状态：采纳
- 日期：2026-10-28
- 相关：ADR-0263（外部工具分发）、ADR-0264（首次引导）、ADR-0242（工具坞值守）

## 背景

ADR-0263 / 0264 把「下载 → 解包 → 跑起来」这条路修通了，并用一台 PATH 里剔掉
node/python 的模拟机跑了一遍真下载。那一轮之后还剩六条已知缺陷，共同点是：

**它们只在别人的机器上才会触发，而且不报错。**

自己机器上永远是「装了就能用」，所以这类问题不会被自测发现，只会在用户那里变成
「插件坏了」。分发前必须逐条修掉。

## 决策

### 1. 值守自启项自带守卫（P0）

`install.ps1` 生成的 `watch.vbs` 开头加两条 `FileExists`：node 与 `cli.js` 任一不在就
`WScript.Quit 0` 静默退出。

理由：计划任务归系统管，**卸载插件不会自动摘掉它**。原先是每次登录拉起一个立刻失败的进程，
`wscript` 还会弹错误框——卸载插件的人从此每次开机被骂一次。

守卫放在 vbs 而不是 cli.js 里：cli.js 正是可能被删的那个，它没法给自己守门。

### 2. 值守状态按 vault 分目录（P0）

```
%LOCALAPPDATA%\bz-dock-watch\
  active.json         ← 现在服务哪个库
  vaults/<key>/       ← 每个库各自的 config / status / logs / live
  watch.lock          ← 单实例锁留在根上（一台机器只有一个值守进程）
```

`key` = vault 绝对路径的 FNV-1a 32 位（8 位十六进制）。三处实现必须同值：
`src/core/vault-key.ts`（插件）、`runtime.js` 的 `vaultKeyOf`（值守）、
`install.ps1` 的 `Get-VaultKey`（安装），由 `tests/dock/watchdog-vault-key.test.ts` 钉住
（Windows 上会真跑一次 PowerShell 对比）。

切换库时 `install.ps1` 打印「之前服务的是哪个库」，插件侧的确认框也改成「把值守切到这个库」——
同一台机器只跑一个值守，不能让用户以为两个库都在跑。

一个实现细节值得记下来：PowerShell 里 FNV 的乘法必须走 `[decimal]`。
`[uint64]` 乘法在这里溢出成负数，`-band` 当场抛「值对于 UInt64 太大或太小」；
被 catch 吞掉之后函数返回的是一个**稳定但错误**的哈希 —— 这种错最难查。

### 3. 便携 Node 的归档缓存（P1）

下载成功的归档留一份在 `downloads/tools/.cache/`。重装时先解缓存，不联网。

理由：Defender 见到刚下下来的、无签名的 36MB exe，有相当概率直接隔离。node.exe 不见了
→ 探测判「没有运行时」→ 用户再点一次 → 又从网上拉 36MB。慢网下这一来一回是灾难。

代价是盘上多 36MB；缓存按版本命名，换版本自然失效。

### 4. 企业网的两条出路：镜像源 + 离线包（P1）

- **镜像源**：设置 → 通用 → 在线资源 → 「镜像源」，填 `<基址>/downloads/xxx` 形状的地址，
  下载时优先走它（`repoBases()` 把它排在官方五通道之前）。只影响资源下载，插件自更新仍走官方 tag。
- **离线包**：把仓库 `downloads/` 目录拷到 vault 下的 `bz-offline/downloads/`，便携 Node 的
  归档放 `bz-offline/node/`。插件优先读本地，离线副本同样要过 sha256。

**离线副本为什么要校验**：不校验的话，「本机有个同名文件」就成了免检通道——
这正是供应链攻击最省事的入口，也最容易让用户装上一个半年前的旧版却以为是最新。

### 5. 目录包深校验（P1）

标记文件的 `sizes` 记下每个文件的字节数；`bundleStatus(app, entry, { deep: true })` 逐个 stat。

只在「自检 / 首次引导检测」这种用户明确要求看一眼的时刻做（224 次 stat 约 20–60ms）；
开面板的常规判定仍只看标记。旧标记没有 `sizes` 一律放行——硬判「坏」会让所有人白白重下。

### 6. 大文件进度 + 大索引不占首装（P2）

- `core/net-progress.ts` 用 `fetch` 的 `ReadableStream` 读进度；拿不到流就回落 `requestUrl`
  （无进度但必通）。失败一律返回 null，**不能变成新的故障点**。
- 豆瓣影视索引（7.2MB，走镜像实测 30 秒）改成「按需」：仍列在清单里，但首装默认不勾，
  影院域首次用到时自己拉。它是首装最后一项，卡在那里最像卡死。

## 顺带修掉的一个真 bug

`vaultBasePathOf()` 用 `trimSlashes` 把路径**两头**的斜杠都剪掉。Windows 上毫无症状
（`C:/...` 本来没有前导斜杠），但 macOS/Linux 的 `/Users/x/vault` 会变成 `Users/x/vault`——
一个相对路径。所有 spawn 的 cwd、所有 `fs.stat` 都指向不存在的目录。

改成只剪尾部。这条是模拟环境里「测试桩拼出的路径少了一个前导斜杠」时顺手发现的：
桩是照实现写的，桩错了往往意味着实现也错了。

## 后果

- 多库用户第一次知道「值守只能服务一个库」，且切换是可逆的（各库状态都留着）。
- 卸载插件后不再被残留自启项骚扰，但它也不会自我删除（系统项只能系统删；`uninstall.ps1 -Purge` 负责）。
- 企业网用户有了两条不依赖系统代理的路；代价是多一个设置项与一段帮助文案。
- 首装少下 7.2MB、少等约 30 秒。

## 已知限制

- 值守服务哪个库仍是**单点**：一台机器同时只能有一个库享受「Obsidian 关着也照跑」。
  要并行得改成每库一个进程 + 每库一个计划任务，那是另一个量级的改动。
- 镜像源只覆盖资源下载；自更新不跟随镜像（有意为之：主程序不走第三方通道）。
- 深校验只比字节数，不比内容 hash。文件被等长替换抓不到——那种情况已经不是「坏掉」，
  是「被替换」，该由签名而不是字节数来管。
