# ADR-0251 · 同一脚本不许并发：在工具坞这一层管，脚本自己不加锁

日期：2026-10-23 · 状态：已采纳 · 关联：ADR-0250（离场运行判活）、ADR-0242（离线值守）、
ADR-0236（bz 调度）、`src/dock/ui.ts` 的 `runningNowOf` / `makeRunBtn` / `syncRunBtns`、
`src/dock/scheduler.ts` 的 `runOne`

## 背景

2026-10-23 用户提了两件事：

> 1 是否可以改成只有脚本运行完成后，才能运行下一次，无论是手动还是自动，保证同一个脚本不会
> 同时运行多个
> 2 按照真实时间

第一版做错了方向：在**脚本里**加 `run.lock`（`wx` 独占创建 + pid 判活）。用户当场纠正：

> 这个限制，不应该限制脚本，而是在 bz 测和值守测来限制，只是在工具坞中使用有并发限制

理由站得住：脚本是独立可跑的（终端里手敲、别的调度器拉、用户自己写 cron）。**能同时跑几个**
是调用方的事，不是工具的属性。工具里塞一把锁，等于把「谁的上下文」这个判断硬编码进了工具 ——
在终端里跑第二个实例的人会莫名其妙被拦住，而且拦它的还是它自己的数据文件目录。

最终形态（第三条指令）：

> 最简单的实现，如果脚本在运行，工具坞的运行按钮不可点击即可，脚本完成后解放按钮

## 决策

### 1. 判据只有一个：`runningNowOf(v)`

```
在场（bz 亲手拉起）        → liveRunOf(id) 非空
离场（值守拉起）          → offlineRunOf(v) 非空（ADR-0250 那套：running 记录 + 90 秒心跳）
```

两种「在跑」在界面上是同一种禁用理由，一句话说清是哪一种（在场 / 值守）。判据放在
`ui.ts` 一处，`canStart()` 直接带上它 —— 这样所有拿 `canStart` 做门槛的入口
（卡片、详情、右键菜单、熔断补跑）一起被覆盖，不会这边拦了那边漏。

### 2. 两个运行按钮合并成 `makeRunBtn()`

卡片和详情页原来各自铺一份 `uiBtn({ label: '运行' … })`。合并成一个工厂函数，顺手把
`data-bz-run-btn="<toolId>"` 挂在按钮上 —— **轮询靠这个标记找人**，不用整页重画。

### 3. 跑完自动解锁：5 秒一拍只改 `disabled`

值守那轮开跑时面板可能已经开着，跑完也没有任何人通知 bz。所以：

- `openDock` 起一口 5 秒的拍（`ensureRunGateTick`），`closeDock` / `unloadDock` 停；
- 每拍对画面上所有 `data-bz-run-btn` 重新算一次（`runningNowFresh` **当场读 `runs.json`**，
  不信视图里那份可能已经过期的快照）；
- **只改 `disabled` / `title`，不重画** —— 重画会把参数表单的草稿和滚动位置一起冲掉。

不画进度条、不改布局：按钮灰着 + 悬停一句「值守那轮还在跑 —— 跑完按钮自己会亮」，
就是全部界面成本。

### 4. 旁路也堵上，但只堵不新增限制

按钮之外的启动路径一共有三条，全部汇到 `runFlow()`：展示板动作（`runBoardAction`）、
右键菜单 / 熔断补跑（`resumeAndRetry`）、以及按钮本身。在 `runFlow()` 开头加一道同样的判断，
`notice` 一句「这次没有启动：…」就返回 —— 用户不会再遇到「点了没反应」。

调度器（`scheduler.ts` 的 `runOne`）同样加一行：`liveRunOf || offlineRunOf` 就 `return 'skip'`
（不算失败、不进冷却、台账不动）。它和值守的分工本来由 `lease` / `defer` 协调，这一行只是
防「手动那轮还在跑，正好 9:00 到了」。

### 5. 脚本侧：一个字节都不动

三个工具（iamtxt / heybox / steam-classify）与白菜价雷达一样，**没有**新增任何锁。
`steam-cheap-radar` 里那把既有的 `run.lock` 保留 —— 它防的是「两个实例同时 read-modify-write
把 `deals.json` / `cache.json` 覆盖掉」，与工具坞这层不冲突；新工具不再效仿。

代价写清楚：**工具坞的按钮只管工具坞**。终端里同时开两个实例，bz 拦不住，也不该拦。

## 代价与边界

- **90 秒判据的边界**：工具被杀、残骸记录还挂着 `running` 时，最坏 90 秒内按钮仍灰着。
  这是刻意的 —— 宁可晚 90 秒解锁，也不要把「正在写文件的那一轮」当成结束。
- **没有心跳的工具**（iamtxt 一轮 0.4 秒、不写 `running` 记录）：离场那半判不出来。
  它本来就快得撞不上，且签到幂等（「今天已签过」），不值得为它加心跳。
- **不重画的代价**：按钮的 `title` 是唯一提示，不弹窗、不 toast。用户要的是「点不了」，
  不是「被告知点不了」。
