# ADR-0253 「关闭 Obsidian 后」这条触发：一枚脉冲，不是一次卸载里的执行

- 日期：2026-10-24
- 状态：已采纳
- 相关：ADR-0252（契约 v2）、ADR-0242（离线值守）、ADR-0236（调度）

## 背景

用户有一份常驻 `powershell` 守护（`CONFIG/SCRIPTS/PowerShell/auto_git.ps1`）：轮询 Obsidian 进程，
进程一消失就把 vault 提交并推到 GitHub + Gitee，顺带做加密备份。它工作得挺好，但它是**另一套调度**——
和工具坞的规则表互不相干，出没出问题只能看系统通知。

要把它收进工具坞，缺的是一种触发：**关闭 Obsidian 后**。契约 v2 的九种触发里，
`on-launch` 是启动、`panel-open` 是开面板，没有「退出」。

直觉做法是在 `onunload` 里直接起进程。不成立：宿主正在退出，Windows 上子进程大概率还没 `exec`
就被一起收掉，用户看到的是「配了却不跑」，而且一条日志都没有。

## 决策

1. **新增触发 `{ kind: 'obsidian-exit' }`**，归事件类（`isEventTrigger` 为真 → 界面上不显示
   「下次预计」，因为它等的是事件不是钟点）。

2. **插件只留一枚脉冲。** `onunload` 里同步写 `<数据目录>/dock.exit.json`：
   `{"at":"<ISO>","pid":<当前进程号>}`。只记一笔，不起进程。

3. **下一拍兑现。** `tickOnce` 在锁内读脉冲，`exitPulseFires()` 判为真就把
   `{kind:'obsidian-exit'}` 追加进这一拍的事件表；`runTick` 正常返回后**删除脉冲**（消费即删）。
   拍失败或被跳过就不删，下一拍再来。

4. **谁执行。** Obsidian 关着的时候是值守进程在拍 —— 它天然是这条触发的主执行者，不需要额外接线。
   值守也没装/没跑，就等下次打开 Obsidian 的第一拍补跑：用户看到的是「上次关的时候该同步的那次，
   这次开机补上了」。

5. **判据三条，宁窄勿宽。** 误报的代价是**每重载一次插件就同步一遍仓库**，比漏一次贵得多：
   - 脉冲读不出时间 → 不算（判不出就不跑，`rules.ts` 的同一条纪律）；
   - 脉冲里的进程号等于读它的进程 → 那只是**重载/禁用插件**，不算关闭；
   - 那个进程号**还活着** → Obsidian 根本没关（多窗口场景，先关的那个只卸载了自己）；
   - 拿不到 `process.kill`（探测不了）→ 当作活着，不跑。

## 后果

- 「重载插件」不会触发同步：`Obsidian` 重载插件是同一个渲染进程，进程号没变。
- 「重启应用」若换了渲染进程号，会被当成一次关闭 —— 代价是一次幂等的 git 同步
  （没有改动就只写一条「没有改动」的记录，不产生提交）。这个代价换「不往 `onunload` 里塞执行逻辑」，
  划算。
- 脉冲是**一次性**的：同一枚脉冲不会让两条规则各跑一遍以上，也不会在下次打开时重放。
- 移动端不写脉冲（没有 `fs`），也不存在「关闭桌面 Obsidian」的语义。

## 附带

同一轮把 `auto_git.ps1` 的「跑一次」那半边抽成了工具坞工具 `auto-git`
（`CONFIG/SCRIPTS/DockTools/auto-git/`：`manifest.json` + `main.mjs` + `sync.ps1`），
默认规则就是这条触发。常驻守护那份脚本原样保留，两者互不影响。
