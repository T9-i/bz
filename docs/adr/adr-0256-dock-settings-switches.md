# ADR-0256 工具坞设置页：只留能按的开关

- 日期：2026-10-24
- 状态：**已被 ADR-0257 取代**（当天同一批改动：用户判定五个开关都不值得给，设置页整节退役）
- 相关：ADR-0252（契约 v2）、ADR-0235（声明与登记）、ADR-0242（离线值守）、ADR-0255（到点即醒）、ADR-0257（取代本文）

## 背景

设置页「工具坞」一组六行，其中三行是**只能看的现状**：值守状态（心跳/上次跑了谁）、
已登记工具（一个数字）、当前调度锁（谁在调度）。真正能按的只剩三个开关，而它们的说明
又都是两三行的原理讲解。结果是一屏字，找一个开关要扫过一段诊断。

更糟的是其中一个开关**是死的**：`notifyMissed`（「漏跑提醒」）在面板 v1 里有消费者
（`.scratch/dock-old-ui.ts` 里那句 `if (!readDockSwitch('notifyMissed')) return`），v2 重写面板时
连整块逻辑一起没了，`dock.json` 里的字段、设置页那一行却留着 —— 点了一点反应都没有。
ADR-0252 自己写过「给一个开着却不起作用的开关，比没有这个开关更糟」，这一条被自己违反了一次。

## 决策

### 1. 设置页只放开关，现状归面板

删掉「值守状态 / 已登记工具 / 当前调度锁」三行。**这不是删信息，是删错了地方的信息**：
它们都是「现在怎么样」，面板里本来就有（卡片的运行点阵、运行记录、详情页），
而且面板是打开就想看现状的地方；设置页是用完就走的。

### 2. 删掉 `notifyMissed`，不补实现

v2 的到期判据本身就是补跑：`daily` 规则只要今天到点还没跑过，下一拍就会跑；
`interval` 同理。也就是说「该跑的时候没跑」这件事在 v2 里**不会留下一个空洞等人提醒** ——
它会在下次能跑的时候直接跑。所以「漏跑提醒」没有可提醒的对象，删掉字段、删掉设置行；
旧 `dock.json` 里残留的这个键在读侧直接忽略（`parse.ts`），不回写、不报错。

### 3. 新增三个开关，每个都有消费者

| 开关 | 键 | 谁读它 | 关掉之后 |
|---|---|---|---|
| 连续失败就暂停 | `breaker` | `kernel.settle` / `kernel.reclaimStale`（`tickOnce` 把 `registry.breaker` 传进去） | 失败次数照记、15 分钟冷却照走，只是不自动停手 |
| 跑成功也提醒 | `notifySuccess` | `host.announce`（只对 `auto: true` 的那次生效） | 自动跑成功不弹通知；**手动点的那次永远报**，人刚点了按钮得有个回音 |
| 状态栏显示在跑几个 | `statusbar` | `statusbar.render`（设置页改完立刻 `refreshDockStatusBar()`） | 状态栏这一块收起（`.is-off` → `display:none`），不是留一个空壳 |

三个键全缺省 `true`：提示类开关缺省关掉等于「默认不吭声」，出问题更难发现。

值守侧读的是同一份登记表、同一段 `tickOnce`，所以 `tools/dock-watch/dock-core.cjs` 必须重打
（`node scripts/build-dock-watch.mjs`）—— 不重打，值守那边还在按旧判据跑，`breaker` 在离线时段失效。

### 4. 按「什么时候发生」重分组

| 组 | 行 |
|---|---|
| 工具坞运行 | 自动运行、连续失败就暂停 |
| 提醒与显示 | 跑成功也提醒、状态栏显示在跑几个 |
| 关闭 Obsidian 之后 | 也继续跑自动任务（原 `watchdog`） |

描述只回答「关掉会怎样」，一句为止；原理、路径（`tools/dock-watch/README.md`）、装法都不进设置页。

## 后果

- **契约**：`DockRegistry` 少一个字段（`notifyMissed`）、多三个（`notifySuccess` / `statusbar` / `breaker`），
  `REGISTRY_VERSION` 不动 —— 读侧本来就只认已知键，旧文件不会因此整份作废。
- **设置页可见项 6 → 5**（契约锁基线同步更新）；三组卡片替代单组六行。
- **生成物**：`tools/dock-watch/dock-core.cjs` + `core-version.json` 需重建（已重建、随本次提交入库）。
- **代价**：设置页里再也看不到「值守在不在跑」。这是有意的 —— 那是面板的事；
  真需要体检时看 `%LOCALAPPDATA%\bz-dock-watch\status.json`，或从面板的运行状态反推。
