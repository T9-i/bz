# ADR-0252 工具坞契约 v2：一把锁、两本账、工单号

- 日期：2026-10-24
- 状态：已采纳
- 取代：ADR-0235（声明与登记）、ADR-0236（调度）、ADR-0237（文件名）、ADR-0239（数据与信任）、
  ADR-0242（离线值守，**暂缓**）、ADR-0248（状态文件）、ADR-0250（离线进度）、ADR-0251（运行闸）
- 相关：ADR-0243/0249（展示板）、ADR-0244（询问）、ADR-0106（UI 单源）

## 背景

v1 的骨架里有三条根假设，出事都出在它们身上：

1. **两个调度者靠客气共存**。插件一个 tick、值守一个 tick，两套冷却、两套在跑集合、两套抖动，
   靠租约互相谦让。先把账记上、再起进程（`patchRuleFired` → run）：崩在这两步之间，这一轮永远丢；
   抖动挂在内存定时器上：进程一关，账记了、活没了。
2. **一个文件装两种事实、两个写者**。`dock-state.json` 里既有规则（人定的）又有记账（机器记的），
   面板与调度器都读-改-写整份。原子写只防半截文件，不防丢更新。
3. **结果靠时间窗猜**。跑完回头翻 `runs.json`，找「起跑后 2 秒内最晚那条」当成本次结果；
   同样的规则在插件里写一遍、值守里写一遍，靠注释提醒彼此对齐。issue 544/552 两次误报都出在这儿。

## 决策

**契约升到 v2，不提供任何兼容。** 旧文件不读、旧字段不认；宁可让人重新登记一次，
也不背「读到旧文件就回落」的分支——那些分支正是上一版说不清问题的来源。

1. **执行权变成一把锁。** 数据目录的 `dock.lock`：排他创建、90 秒过期可抢（抢前先 `rename` 搬走旧锁）、
   持锁者每 20 秒续期。拿不到锁就这一拍什么都不做。租约、让位、两套冷却全部删除。
2. **意图与事实分家。** `dock.intent.json`（面板写：启用/自动/规则）与 `dock.runtime.json`
   （内核写：每条规则的 `lastFiredAt`/`pending`/`lastStatus` + 失败计数/熔断）。
   一个文件一个写者，谁都不碰对方那份。
3. **待办落盘。** 到点的时刻与工单号写进 `runtime` 的 `pending:{runId,dueAt,claimedAt}`，
   不再挂内存定时器。崩在中间，下一拍读到 pending 接着办。
4. **工单号对账。** bz 生成 `BZ_DOCK_RUN_ID` 注入；工具把它原样写进 `runs.jsonl` 那行。
   判定收敛成唯一一个 `judgeRun(outcome, records)`（`exec.ts`），插件/值守/测试同源。
   查不到就明说「这次没留记录」，绝不拿上一条充数。
5. **记录改 JSON Lines。** 一行一次运行、只写终态；跑着的时候用独立的 `heartbeat.json` 表达，
   不再「每 8 秒重写整份记录当心跳」。
6. **凭据不走命令行。** `secret` 参数改注入 `BZ_DOCK_SECRET_<KEY>` 环境变量——
   命令行在任务管理器 / `ps` 里人人可见。
7. **面板重写。** 一个 overlay、两个视图（列表/详情），**替换**而不是层层叠加。
   视觉沿用宿主变量，不引入自己的主题层。

## 后果

- **接受**：已有工具的记录、规则、失败计数全部作废；四个现役工具需要按 v2 重写落账部分；
  面板要重新登记与授权一次。
- **接受（已在补记里偿还）**：重写当时 `tools/dock-watch/` 还没迁到 v2，所以先停用它、
  设置页如实写「本版暂不支持」、`watchdog` 缺省 false —— 给一个开着却不起作用的开关，
  比没有这个开关更糟。补记里它已经迁完，`watchdog` 恢复缺省 true。
- **收益**：跑丢、跑重、误报成功三类事故从机制上消失；每一条「没跑」都有原因可查；
  判据只有一份实现。

## 补记（同日）：值守进程迁到 v2 —— 调度只剩一处

重写当时把值守停下来是**暂时的**，不是设计结论。这一节记它怎么回来的。

### 做法：不是「让值守复用判据」，是「让值守只剩触发」

上一版把 `ruleDue` 打包过去就算复用了，排班、记账、判成功仍各写一遍 —— 于是有
`decide.js` 的 `runGate`、`ledger.js` 的 `markRuleFired`、以及一份与 `runner.ts`
「逐条对齐」的 `resolveOk`。这次换了个切法：

- 新建 `src/dock/tick-once.ts` 的 **`tickOnce()`** —— 拿锁 → 锁内重读登记表 → 收尸 → **`runTick`** → 放锁。
  插件（`host.ts`）与值守（`watch.js`）各自只调它。
- 新建 `src/dock/watch-core.ts` 作为值守唯一的导出面，`dock-core.cjs` 从它打出。
  打包后扫产物里有没有 `obsidian`，有就删产物报错 —— 防止有人往导出面里塞宿主模块。
- 值守包删掉 `decide.js` / `ledger.js` / `launch.js`（约 530 行），`watch.js` 从 386 行降到 ~230 行，
  只剩三件事：装配、什么时候调、写本机状态。
- **租约与让位一并删除**。两边抢同一把 `dock.lock`，抢不到就 `skipped: 'locked'`。
  「谁在场」不再是正确性的前提，只是个诊断字段。

### 顺带修掉的四个真 bug（都是这次迁移挖出来的）

1. **内核与执行层的工单号不是同一个。** `runTick` 生成 `pending.runId` 传给 `execute`，
   但 `runToolNow` 内部又 `makeRunId()` 造了一个 —— `settle` 记的号与工具写进 `runs.jsonl`
   的号永远不同，对账当场失效（面板按 `lastRunId` 找记录会找不到）。现在 `runToolNow` 收 `runId`。
2. **`cwd` 缺省没实现。** 契约写「缺省 = 声明所在目录」，代码里传的是 `entry.cwd`（undefined），
   子进程继承宿主进程的 cwd —— 插件里是 Obsidian 目录，值守里是仓库根，`args:['main.mjs']`
   一律失效。症状正是「面板能跑、值守报找不到文件」。
3. **`writeRuntime` 永远不会跳过写。** `updatedAt` 每次都是新的，`writeIfChanged` 拿它一起比
   等于每次都比出「变了」。现在比较时摘掉那一格。
4. **收尸用的是 `claimedAt`。** 那是**排队**时刻，抖动可以把 `dueAt` 推到 12 小时后 ——
   拿它判「卡住了没有」会把还在排队的当成尸体。现在 `pending` 分 `startedAt`（真起跑）与
   `attempts`（起过几次）：没有 `startedAt` 的一律不碰；超时的按次数上限重跑或判废。

### 一处从「假」改成「真」

设置页「关掉 Obsidian 也让自动任务跑」恢复成真开关，旁边加一行「值守状态」读
`%LOCALAPPDATA%z-dock-watch\status.json`（心跳 / mode / 本次跑了几次 / 上次跑的谁 / 上次错误）。
两侧目录推导的**一致性**由 `tests/dock/watchdog-path.test.ts` 钉死 —— 两条代码无法共享，
就让测试来保证它们算的是同一个地方。

### 心跳终于有了读者

上一版 `heartbeat.json` 只被工具写、没有任何人读 —— 一个没人看的心跳，说它「用来判死」是假的。
这一版让它真的有用：`view.ts` 读它，面板用它在卡片状态点与详情页说「**后台正在跑**」，
并把「运行」按钮禁掉。之前值守在跑的时候面板显示「什么都没发生」，用户再点一次就会卡在锁上
（拿不到锁、静默返回）—— 现在按下去之前就知道该等。

⚠️ 它**仍然不参与判成功失败**：判定看进程退出 + `runs.jsonl` 里 `runId` 那一条。
心跳只回答「此刻有没有人在跑它」。

### 契约文档的一处自我修正

`docs/dock-tool-guide.md` 原先写「bz 看到心跳 60 秒没动就当这次死了」。**这是假的**：
判定只看进程退出 + `runId` 对账，超时强杀线是 10 分钟。心跳的用处只是让人看得见长任务还在动。
文档已改，免得工具作者照着一条不存在的规则写兜底。

### 验证

- `tools/dock-watch/test/watcher.test.mjs` 是端到端：临时 vault + 真工具进程 + 真 tick，
  断言记录里的 `runId` 就是内核给的那个、`pending` 被清掉、开关关着不跑、锁不在手里不抢、没网不记账（7 条）。
- 工具坞域 42 条（新增收尸 4 条）、全量 9039 条通过。
