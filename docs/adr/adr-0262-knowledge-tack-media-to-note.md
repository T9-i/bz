# ADR-0262 挂到笔记只搬嵌入、不搬正文：转录留在影像笔记里

- 日期：2026-10-26
- 状态：已采纳（知识盒列表右键菜单新增「挂到笔记…」，只对图版与影像出）
- 相关：ADR-0073（四种文献类型）、ADR-0222（视频正文只剩「只修错」校对一档）、ADR-0071（AI 与落盘回插件侧）、ADR-0261（视频笔记的标题/简介只认转写文稿）、ADR-0245（删除走库内回收站）

## 背景

一条影像文献（`文献盒/王虹证明三维挂谷集维数为三并解释转针问题.md`）的实际作用往往只是某篇已有笔记的**材料补充**——用户想把视频挂到 `文献盒/挂谷集.md` 后面，而不是让它在文献盒里另立一条。图版同理（一张图常常是某个术语的例证）。

诉求提出时的最初设想更激进：**不再生成影像笔记**，直接把视频追加到目标笔记后面。这条路被否，因为它一次会掉三样东西：

1. **转录没有家**。视频笔记的正文就是转写/校对稿（`generateVideoNote` 的 `body = [fm, 校对稿, 视频双链]`），它既是这条视频唯一的内容载体，也是自动关联、向量索引、提炼成卡的入口。取消笔记 = 转录必须塞进目标笔记正文，或退化成库外孤岛文件。前者让术语笔记变成「150 字定义 + 3000 字口语稿」，索引块被转录主导，那篇笔记的语义中心从「挂谷集是什么」漂到「王虹讲了什么」；后者在 Obsidian 里读不到，得跳出去看。
2. **元数据九键没有落点**。title / tags / summary / source / author / sourceTitle / type / domain 是 AI 从转录里抽的，目标笔记已有自己的 frontmatter，不能覆盖。
3. **历史没有可打开项**。`literature.json` 任务的 `notePath` 指着那条笔记，取消后历史只剩一条无落点记录。

## 决策

1. **只搬嵌入，不搬正文**。挂载块 = 源笔记正文里的 `![[…]]` 媒体（视频 / 图片，尺寸别名原样保留、同路径去重），包成：

   ```markdown
   > [!quote] [[王虹证明三维挂谷集维数为三并解释转针问题]]
   > ![[CONFIG/APPENDIX/…_BV1Z6H56oEcQ_clip_00-01-49-00-03-56_crf23.mp4]]
   ```

   转录与解读留在源笔记。目标笔记拿到的语义是「这里有一条材料，内容去那篇看」——**一段文字只有一个家**。搬正文会让同一段文字在库里出现两份：向量索引重复、每周知识动态报「高度重合」、且从此双写分叉（改一边不同步另一边）。

   块头的双链**只写标题、不带目录**（`文献盒/挂谷集.md` → `[[挂谷集]]`）：块头是给人看的一行，带路径会把 callout 标题撑长；重名消歧交给 Obsidian——同名笔记的链接在编辑器里会显示完整路径，一眼能看出来。代价是整库出现同名笔记时简链接可能指向另一篇，此时改块头加路径即可，功能不记「已挂」状态，改完照样幂等。

2. **幂等锚点 = 块头**。`> [!quote] <源双链>` 这行就是锚点：再挂一次不叠加，整块就地换成最新嵌入（源笔记换了视频能跟上）；用户手删掉块 = 取下，重挂照常追加回来。块范围 = 从块头起的**连续 `>` 行**，遇空行即止——同一篇笔记连挂两条材料时，两块靠这个空行分界。

3. **只给图版与影像出这一项**。名词 / 段落的正文是一段文字，没有可搬的嵌入；把它们的正文搬过去就是第 1 条明令禁止的事。

4. **目标排除素材型文献与自身**。图版 / 影像笔记的正文本身就是媒体，挂进去会变成两条材料挤一篇；自身挂自己是循环。

5. **写入只动文件末尾**（`src/knowledge/tack.ts`）：原有正文与 frontmatter 零扰动、换行符保真（CRLF 不变）、块前恰好一个空行、尾部多余空行收成一个。内容一致的重复调用不写盘（省一次磁盘事件）。

6. **不写 `related`**。目标笔记被改动后基准哈希变化，60 秒防抖的自动关联会重跑并自行补上双链；手写反而与 AI 裁判的判定打架。要立刻生效走已有的 `link now` 显式通道。

7. **目标解析三级兜底**：`路径 → 简链接（metadataCache）→ 三盒缓存按 title 精确匹配`。第三级是因为候选胶囊填的是 AI 生成的标题，未必等于文件名（`note-gen` 用 `sanitizeMdTitle(title)` 落盘，多数时候一致，但不能赌）。

## 后果

- 「取消影像笔记」这条路被明确堵上：想省文献盒里的一条笔记，代价是转录失去可检索的家，不划算。文献盒被影像笔记塞满的问题该由**类型过滤**（已有「全部/视频/术语」档）解决，不是把内容倒进别人的笔记。
- 目标笔记里出现一块不由它自己维护的内容。源笔记被删时它不会自动消失（现有的 `vault:md-deleted` 承接只管数据条目，不管别人正文里的嵌入）——Obsidian 里表现为一条未解析链接，肉眼可见。清理时按块头锚点整块删即可，与幂等是同一套机制。
- 挂载不参与自动关联的候选池：它是动词（写盘动作），不是名词（frontmatter 关系）。反向要看「哪些笔记挂了它」，靠 Obsidian 的反向链接面板——块里的双链天然支持。
- 挂载允许出盒（手写路径能指向三盒外的笔记）。盒外笔记不参与向量索引与自动关联，所以「索引污染」这一层担忧不成立；这也让「挂到日记 / 主页」这类用法直接可用。

## 备选（未采纳）

- **不生成影像笔记，直接把视频追加到目标笔记**：见背景三条，转录与元数据都没有落点。若坚持一条笔记装完，唯一可接受的形态是转录进**折叠 callout**（`> [!note]-`），但它只影响阅读视图、不影响索引切块，术语笔记的语义中心照样漂移——不采纳。
- **挂载时只追加一个普通双链（不嵌视频）**：目标笔记里点一下要跳走，材料不可见；嵌入才是「材料补充」的本意。
- **把源笔记的 `summary` 也追加一行当概要**：可选增强，本次不做。做的话它是概要（60 字内），不是转录，不违反第 1 条。
- **用 `%%…%%` 注释做幂等锚点**：会往用户笔记里塞不可见字符；块头本身已经唯一（源路径唯一），不需要。
- **挂载时顺手写 `related`**：与自动关联重复且可能冲突，见决策 6。
