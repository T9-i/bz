# ADR-0243 · 工具坞：展示板 —— 脚本画 `panel.html`，面板用沙箱 iframe 内嵌

日期：2026-10-14 · 状态：已采纳 · 关联：ADR-0235（外部工具契约）、ADR-0237（文件名惯例）、
ADR-0239（面板数据与信任分家）、ADR-0242（离线值守）、`docs/dock-tool-guide.md`

## 背景

工具坞的详情页一直是「bz 排版、工具填数」：统计条、元信息、自动运行、运行台、运行记录 ——
每一块都是 bz 定的版式，工具能影响的最多是一句 `message` 和几个 `metrics` 数字。

但有些工具**自己知道该展示什么**：签到脚本知道这月攒了多少积分、抓取脚本知道今天入库几条。
这些形状事先枚举不完，bz 也不该替每个工具设计版式。用户提出的落点：

> 在运行台上面添加一个展示脚本自行的 html，可以允许任何内容，比如每日签到显示积分数。

于是有了**展示板**：详情页里给工具一块地方，它爱画什么画什么。

## 决策

### 1. 载体：工具目录里的 `panel.html`（与其它几份文件同址同性质）

与 `manifest.json` / `runs.json` / `data.json` 一样住工具目录，一样是**工具写、bz 只读**。
不塞进 `runs.json` 的字段，理由有两层：

- **性质不同**：记录是流水（每次一条，只增），展示板是现状（只该有最新一份）。把它塞进记录，
  等于每次跑都往流水里抄一遍同样的 HTML，还得定「取最新那条」的规矩；
- **可手改**：调样式时不用跑一遍脚本 —— 改完文件打开面板就看到。这对「审美靠试」的活是刚需。

代价：工具得**记得在数据变化时重写它**（签到脚本跑完把积分数更新进去），且多一个要维护的文件。

### 2. 渲染：沙箱 iframe，不是净化后插进 DOM

`<iframe sandbox="allow-same-origin">` 内嵌 `srcdoc`。

**为什么不净化后直接插 DOM**：净化做得再细，也挡不住两件必出的事 —— 一段 `<style>` 会串色到
整个面板（面板的 CSS 变量、按钮、布局全在同一个文档里），一个没闭合的标签会把后面的 DOM 吃掉。
iframe 把这两样天然关在框里：展示板的样式只能影响它自己。

**为什么带 `allow-same-origin`**：只有一个理由 —— 能读 `contentDocument` 量内容高度。
不带它量不到，只能写死高度（展示板从「两行数字」到「一张表」高度差好几倍）。

**为什么刻意不给 `allow-scripts`**：里头的 `<script>`、`on*` 属性、`javascript:` URL 一律不执行。

这条要说清楚**不是**「不信任写脚本的人」—— 那个人本来就能在这台机器上跑任意命令（ADR-0239 的
信任门就是为这件事设的），防他毫无意义。真正的理由有三条：

1. **防误伤**：一段写坏的展示板不该有能力把面板搞乱；
2. **防手改翻车**：`panel.html` 是给人手改的，改的人未必知道自己在什么上下文里；
3. **防口子被当日后的能力用**：一旦「面板里能塞会跑的代码」成立，后来者一定会拿它做正经功能，
   到那时这条边界就再也收不回来了。现在的形态是「一块画布」，只做画布。

### 3. 位置与高度

- **整宽，且排在详情页最前**（统计条之前）—— 位置后来调过一次：原先放在「自动运行」与
  「运行台 / 运行记录」两栏之间，但他要的第一眼是「这个工具给我看了什么」，不是它的元信息。
  整宽是必须的：展示板常要放表格或一行几个数字，挤进半栏的左栏会立刻变形；
- **不配标题**：摆在最前就是让它自己说话，再加一行「展示板」是面板在自说自话
  （iframe 的 `title` 属性留给读屏，那里需要一个名字）；
- **文件不存在（或只有空白）→ 整块不出现**，不留空框；
- 渲染后按 `contentDocument` 撑到内容高，**上限 520px** —— 超了让 iframe 自己滚，
  免得把参数表单和运行按钮挤到屏幕外；
- **上限 512 KB**：超了不渲染并说明。展示板是「一眼看完的几行数」，想放长文该去写手册。

### 4. 主题：面板只灌一小撮变量，写在 `body` 的 `style` 属性上

面板把自己当前主题的 CSS 变量抽一组，连同几条基线样式，合成一个 `style` 属性值挂在展示板的
`body` 上（底色 / 文字 / 描边 / 品牌色 / 圆角 / 字体 / 间距）。展示板拿 `var(--bz-text-1)` 这类
写法就画得出「像是面板的一部分」的东西，深浅色自动跟随。

**为什么不拼一段 `<style>` 塞进去**：`style` 属性本来就支持自定义属性，够用；而且这样这个模块里
一处 `<style>` 字面量都没有 —— **铁律 4 的唯一注入点守卫（ADR-0199）不必为它开第二个口子**。

代价是**内联样式的优先级高于任何选择器**：展示板没法用普通规则改那几条基线（要改得上
`!important`）。所以基线只留最必要的：`margin:0`（body 默认有 8px 外边距）、
`background:transparent`（iframe 内容默认白底，不设就是深色面板里一块白），再加内边距与字体
这几条观感默认值。要摆布自己的内容，请在自己的元素上写样式 —— 那不受内联基线影响。

**只给这一小撮**：给全套等于把面板内部 token 变成公开 API —— 日后想重构任何样式变量，
都得先问过所有已发布的工具。这一小撮够画内容，不够拿来复刻面板本身。

## 明确不做

- **不做多块 / 可拖布局**：一块画布，摆什么由工具自己排。
- **不做脚本 → 面板的实时通信**（`postMessage`）：那需要 `allow-scripts`，等于把 §2 那条边界
  整个推翻。要更新就重写文件（运行完自然会刷新面板）。
- **不做外链资源**：单文件自包含，图片要 `data:` 内联。iframe 里相对路径解析不到工具目录，
  而放行 `file://` 会把整块展示板变成一个读本机文件的通道 —— 不值得。
- **不代写 / 不自动生成 `panel.html`**：bz 一写就成了第二个写者（同 `runs.json` 的理由）。
- **不把它做成工具坞的「一个小工具」**：它就是详情页里的一块，不登记、不进 KPI。

## 后果

- 新增：`declaration.ts` 的 `PANEL_FILENAME` / `panelPathFor` / `readPanelText`；
  `ui.ts` 的 `boardSection` / `boardBaseStyle` / `fitBoardHeight`；`styles.css` 的 `.bz-dock-board*`。
  （三个 ui.ts 私有函数在 ADR-0244 起被询问框正文共用，改名 `frameBaseStyle` / `fitFrameHeight` /
  抽出 `sandboxFrame`。）
- 工具目录多一个可选文件；**老工具零迁移** —— 没有这个文件的工具，详情页与改动前一模一样。
- 契约文档 `docs/dock-tool-guide.md` 加第 5 份文件（工具写的第 3 份）。
- **铁律 4（唯一注入点）没有被触碰**：主题变量与基线走 `style` 属性，本模块里没有 `<style>`
  字面量，`skin-pack-split-guard` 一个字都不用改 —— 没多出跨域的例外。
- 要认的代价：`srcdoc` 每次打开详情页重建一次（内容大就慢，所以有 512 KB 上限）；
  以及一套**只能靠文档传达**的沙箱规则 —— 脚本作者第一次写 `<script>` 时会发现它不跑，
  所以文档里要把「沙箱里没有 JS」写在显眼处，而不是让他自己试出来。

## 补记（2026-10-15 · 520 px 上限废掉）

上面决策里的「高度 520 px 上限、超了框内滚」已废：框里滚出来的那根是**原生**滚动条（样式管不着、
不跟主题，Windows 上还带箭头），用户当天报「展示窗口不显示滚动条」指的就是它。改成**框跟着内容
长**、滚动交给面板内容区（`.bz-dock-body`，本来就有），并且框文档的**根元素**上补了 `scrollbar-width: none`
（界面级隐藏滚动条那套够不着框里 —— 独立文档；挂 `<body>` 无效，实测）；背景与取舍见 ADR-0244 的补记。512 KB 字节上限不动。
