# ADR-0257 工具坞不再有全域开关：设置页整节退役

- 日期：2026-10-24
- 状态：已采纳
- 相关：ADR-0256（上一版：只留能按的开关）、ADR-0252（契约 v2）、ADR-0242（离线值守）、ADR-0235（声明与登记）

## 背景

ADR-0256 把设置页从「三行诊断 + 三个开关」收拾成五个能按的开关，按「什么时候发生」分成三组。
上线当天用户看完的结论是：**这五个都没用，默认全开，全部删掉**。

回头看，这个判断是对的。这五个开关的共性不是「开关不好」，而是**每一扇门都开错了位置**：

| 开关 | 用户真想做那件事时，正确的位置 |
|---|---|
| 自动运行（总闸） | 不想让某个工具跑 → 面板里停用那个工具（`dock.intent.json` 的 `autoRun` / `enabled`） |
| 连续失败就暂停 | 它真挂了三次 → 该去看为什么挂，不是希望它继续挂着跑 |
| 跑成功也提醒 | 嫌吵 → 问题在「它为什么老跑」，关通知只是把信号关掉 |
| 状态栏显示在跑几个 | 不想看 → 那块平时只有「工具坞」三个字，藏起来省不出一寸地方 |
| 关掉 Obsidian 后继续跑 | 不想后台跑 → 该卸掉值守件（那是安装时的一步，不是一个开关的语义） |

再加两条硬事实：**五个都缺省开**（ADR-0256 的决定），也就是绝大多数人一次都不会碰；
而它们全部住在 `dock.json` 里，多一个字段就多一条「读到旧值怎么回落」的分支 ——
契约 v2 重写时最想摆脱的就是这类分支。

## 决策

### 1. 设置页不再出现「工具坞」

`src/dock/settings.ts` 删除；`settings-panel/ui.ts` 里 `DOMAINS` 去掉 `dock` 一条，
`schemaLoaders` 去掉对应 loader，`NAV_SECS` 的「工具」组只剩番茄钟与小橘。

工具坞仍有自己的面板（命令 `bz-dock-open`、状态栏点击）。**工具级的开关、参数、规则表都在面板里**，
一个都没少 —— 删掉的是「跨工具、几乎不动、却要求用户先理解原理」的那一层。

### 2. 五个字段从 `DockRegistry` 删除，行为固定

| 行为 | 固定成 | 落点 |
|---|---|---|
| 自动运行 | 永远开（`tickOnce` 不再判总闸；`planTick` 的 `globalAutoRun` 与 `global-off` 一起去掉） | `tick-once.ts` / `kernel.ts` |
| 熔断 | 永远开（连挂 3 次写 `pausedAt`，面板手动恢复） | `kernel.settle` / `kernel.reclaimStale` |
| 成功通知 | 永远报 | `host.announce` |
| 状态栏 | 常驻 | `statusbar.ts`（连 `.is-off` 样式一起删） |
| 离场调度 | 永远开（装着值守件就让它接手） | `tickOnce` 去掉 `respectWatchdog`；`watch.js` 去掉对应状态分支 |

`REGISTRY_VERSION` **不动**（仍是 3）。登记表读侧本来就只认已知键：旧 `dock.json` 里的
`autoRun` / `watchdog` / `notifySuccess` / `statusbar` / `breaker` / `notifyMissed` 一律丢掉，
不回写、不报错。版本号一升，`parseRegistry` 会把整份旧表按空处理 —— 存量的工具登记会全丢。

### 3. 不留「设置页空壳」

不留一个空分组让人点进去看到空白：域列表里直接没有工具坞这一条。
可见项统计也随之少一个域（设置面板域数 20 → 19）。

## 后果

- **契约锁**：`COUNT_BASELINE` 删 `dock: 5`；`settings-panel.test.ts` 四处域数断言 20 → 19。
- **值守包**：`tickOnce` 的签名与判据都变了，`tools/dock-watch/dock-core.cjs` 必须重打
  （已重打、随本次提交入库），否则离线时段还在按旧字段判。
- **升级路径**：旧 `dock.json` 直接可读；**如果以前手动关过某个开关，升级后它会变回开** ——
  这正是这次决策的目的（默认就是最合理的行为，不保留「上次被我关掉」的记忆）。
- **诊断口径不变**：值守在不在跑、最近跑了谁、锁在谁手里，仍然只能从面板与
  `%LOCALAPPDATA%\bz-dock-watch\status.json` 看。设置页从来不是这些信息该待的地方（ADR-0256 §1）。
- **`watchdog-status.ts` 保留 `off` / `auto-off` 两条文案分支**：读的是值守写的 `status.json`，
  老文件里可能还留着这两个值；留着只是为了让旧状态不至于显示成未知，不是留着开关。
